# 课表提醒

一个极简的 Android 课表提醒应用：**识别课表截图 → 到点静默提醒 → 由手表完成真正的唤醒**。

> 起因：上课容易迟到，手机放在包里听不见。戴着手表，但需要一种「手机不出声、手表能震」的提醒方式。

---

## 它解决什么问题

| 需求 | 做法 |
| --- | --- |
| 不想每学期手动录一遍课表 | 从教务系统导出的课表截图里自动识别课程和作息时间 |
| 手机在包里，响铃听不到 | 不响铃、不震动，只在通知栏留一条静默提醒 |
| 需要真正叫得动人 | 通知同步到手表，由手表震动 |
| 课表每周都在变 | 周次按日期自动推算，不用手动改 |

---

## 功能

- **课表导入（4 条路，按准确率排序）**
  1. **剪贴板导入**（推荐）：在教务系统网页里全选复制，App 里点一下即导入。文本是系统给的，**没有识别误差**，实测整学期 21 条时间条目全部正确
  2. **App 内截图识别**：内置离线 PP-OCR，支持有框线课表和**无框线**（教务系统网页那种彩色色块）两种版式
  3. **桌面端识别**：Python 脚本把课表图片切格逐格 OCR，输出可导入的 JSON
  4. **手动录入**：任何学校都能用，不受格式限制
- **课表词典纠正**：用已导入的准确课表去纠正之后截图识别出的错字（`人工智` → `人工智能与信息技术基础A_05`）
- **静默提醒**：`AlarmManager.setAlarmClock` 定时，到点弹一条无声无震通知（可选发短信）
- **周次自动推算**：设置一次学期开始日，之后自动计算当前第几周
- **起止周 / 单双周**：不在范围内的课到点自动跳过，不打扰
- **提醒方式可选**：仅通知（推荐）／通知+短信／仅短信
- **闹钟自检**：随时查看「配置了几条 / 系统里还挂着几条」
- **手动编辑**：课程和闹钟都能增删改
- **导入方式可选**：覆盖导入（替换整张课表）／合并导入（只追加新课程）

---

## 为什么默认用「通知」而不是「短信」

最初的设计是发短信给自己，靠短信通知同步到手表。实际踩到三个坑：

1. **单卡手机发给自己不会提醒** —— 系统把「自己发给自己」当成你自己的对话，不打红点也不弹通知
2. **国产系统拦截后台发短信** —— 前台测试能发，后台闹钟触发时被系统拒绝（返回码 32，十几毫秒就失败）
3. **双卡要指定卡** —— 不指定会弹选卡框，破坏「静默」这个前提

**结论：手表不认「短信」，只认「通知」。** 直接由应用自己弹一条静默通知，绕开运营商、短信应用和厂商限制，一步到位。

短信通道仍然保留，可在设置里切换。

## 适用范围（重要，先看这段）

课表截图识别**不是通用功能**。它的解析规则是针对某一类教务系统导出格式调的：

| 环节 | 当前支持的格式 |
| --- | --- |
| 表头 | 「星期一…星期日」或「周一…周日」 |
| 时间栏 | `第(08:00-08:45)` 这类带括号的写法 |
| 周次 | `7-8周`、`第3周` |
| 节次 | `1-2节` |
| 教师 | 带星号，如 `李帅*` |
| 格内顺序 | 课名 → 编号 → 教师 → 周次 → 节次 → 地点 |
| 表格 | 有横竖实线的表格型课表 |

**如果你的课表格式不同**，需要改 `tools/recognize_schedule.py`。改之前先跑：

```bash
python recognize_schedule.py 你的课表.png --debug
```

它会打印网格线、每一格的原始文字、以及每一步的解析结果。**一看就知道卡在哪一步**，不用读源码。

文件顶部的 `PLACE_WORDS` / `PLACE_PREFIXES` / 各个正则都是集中可调参数，通常只改这几个就够。

**「地点识别」本身是通用的** —— 靠「楼/馆/厅/室/操场/报告/园/号」等关键词判断，换成任何学校的楼名都能认出来。

**App 的手工编辑功能与图片格式无关**，任何学校都能直接用（导入 → 手动订正，或者完全手动录入）。

## 快速开始

### 环境要求

| 项目 | 版本 |
| --- | --- |
| Flutter | 3.35+（开发用 3.47.6） |
| Dart | 3.9+ |
| JDK | 17 |
| Android SDK | compileSdk 36 / minSdk 24 |

### 构建

```bash
flutter pub get
flutter build apk --release
```

产物在 `build/app/outputs/flutter-apk/app-release.apk`。

Windows 上一键打包（含引擎版本标记校正、失败自动重试）：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\07-build-and-publish.ps1
```

该脚本按以下顺序查找工具链目录：

1. 环境变量 `DSH_DEVTOOLS`
2. 工程上一级目录下的 `devtools`
3. 备用默认路径

需要把 `flutter`、`git`、`jdk17`、`android-sdk`、`gradle-home`、`pub-cache` 都放在这个目录下，或直接用系统已安装的 Flutter。

### 课表识别（桌面端）

```bash
cd tools
pip install rapidocr-onnxruntime pillow numpy
python recognize_schedule.py 课表图片.png
```

会在图片同目录生成 `课表导入.json`。Windows 上也可以把图片直接拖到 `tools/识别课表.bat` 上。

识别用的是 **RapidOCR**（PaddleOCR 的 ONNX 推理封装），全程本地离线，不需要网络、不上传任何数据。

## 使用流程

### 首选：剪贴板导入（手机端，几秒钟，无识别误差）

1. 手机浏览器打开教务系统课表页
2. 长按表格 → **全选 → 复制**（要包含页面下方的「全部课程清单」）
3. 打开 App → 识别页 → 点 **读取剪贴板并解析**
4. 核对解析结果 → **覆盖导入**（或合并导入）

支持两类文本：URP 系统的「课程清单」格式（`周次>>星期>>节次`），以及常见的一行一门课格式。

### 备选：截图识别（手机端直接识别）

识别页点「选择截图」。会先按「有表格线」的方式切格识别，检测不到表格线时
**自动改用无框线算法**（整图 OCR + 星期表头/时间栏锚点排版），
适合教务系统网页那种彩色色块课表。

> 注意：截图识别受图片清晰度限制。实测图片宽度低于 2000px 时识别率明显下降，
> 能用剪贴板就用剪贴板。

### 备选：桌面端识别（清晰度最高的图走这条）

1. 从教务系统导出课表 PDF / 截图（建议用电脑导出，图片清晰）
2. 桌面端跑识别脚本，得到 `课表导入.json`
3. 传到手机，App 课表页右上角点导入

### 之后

4. 设置页填 **学期开始日**、**提醒方式**、**短信接收号码**（如果用短信）
5. 到系统设置里放行：**自启动**、**后台运行**、**电池优化不限制**

第 5 步很关键 —— 详见下一节。

---

## ⚠️ 国产 ROM 必读

在 vivo / 小米 / OPPO 等系统上，**应用长期不打开会被系统冻结，冻结后系统闹钟不再投递**。

表现：刚装好能提醒，过一两天就再也不响，诊断日志里连「闹钟触发」都没有。

**必须手动放行**（代码绕不过去）：

| 系统 | 路径 |
| --- | --- |
| vivo / iQOO | i管家 → 应用管理 → 课表提醒 → 权限 → 自启动 + 后台运行 |
| | 设置 → 电池 → 后台耗电管理 → 允许后台高耗电 |
| 小米 / 红米 | 设置 → 应用 → 课表提醒 → 省电策略 → 无限制 |

App 内 **闹钟页 → 📄** 可以随时查看健康状态：

```
✔ 闹钟状态正常
配置 24 条 · 系统里挂着 24 条 · 下一个闹钟 10-19 07:50 · 当前第 7 周
```

如果显示「系统里挂着 0 条」，就是被系统清了，点「重新激活闹钟」并检查上面的放行设置。

## 已知限制

- **课表识别不是 100%**：即使格式匹配，教务系统导出的图片里也可能有「下午列宽只有上午一半」这类怪癖，导致相邻两星期的课挤进同一格。识别后需要在 App 里手动订正几处。
- **单卡手机不要用「仅短信」**：发给自己不会触发通知（见上文）。
- **国产 ROM 的冻结问题无法用代码根治**，只能靠用户手动放行。
- Windows 桌面版可以构建，但提醒功能只有 Android 有。
